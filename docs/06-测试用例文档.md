## 2. 详细用例

### TC-ENV-01 Backend 健康检查

- **前置**：Backend 已启动。
- **步骤**：`GET http://localhost:6080/api/v1/health`
- **期望**：HTTP 200，body 含 `"message":"OK"`。

### TC-ENV-02 版本接口

- **步骤**：`GET /api/v1/version`
- **期望**：`currentVersion` 为 `0.301.2`（或与当前 package 一致）。

### TC-ENV-03 Frontend 可访问

- **步骤**：浏览器打开 `http://localhost:6100`
- **期望**：返回 NocoDB Frontend 页面（非长时间 503）。

### TC-AUTH-01 正确账号登录

- **前置**：Meta 中已有用户（如共用 `mlnoco`）。
- **步骤**：6100 登录页输入正确邮箱密码。
- **期望**：进入工作区/Base 列表。

### TC-AUTH-02 错误密码

- **步骤**：输入错误密码。
- **期望**：登录失败提示，不进入主界面。

### TC-DS-02 / TC-DS-03 海量数据源

- **前置**：Backend 含 FK SQL 兼容补丁；网络可达 `192.168.100.99:5432`。
- **步骤**：
  1. 打开 Base → 数据源页面（如 `#/nc/.../?page=data-source`）。
  2. 新增 PostgreSQL 连接：Host/Port/User/Password/Database=`metabase_rpt`。
  3. 测试连接并保存/同步。
- **期望**：
  - 连接成功。
  - **不再**出现含 `UNNEST` / `WITH ORDINALITY` / `syntax error at or near "."` 的失败。
  - 可看到 schema 下表列表（如 `dbo`）。

### TC-DS-06 / TC-DS-07 SQL Server 数据源

- **前置**：Backend/Frontend 已启动；网络可达 SQL Server 测试库。
- **测试库**：

  | 项 | 值 |
  |----|-----|
  | Host | `192.168.1.11` |
  | Port | `5678`（非默认 1433） |
  | User | `sa` |
  | Password | 见内网测试口令 / 环境变量 `NC_MSSQL_PASSWORD` |
  | Database | `Metabase_ODS` |
  | Schema | 业务库常见为 `UFDATA` / `file_source` 等（不一定是 `dbo`）；按实际 schema 填写 searchPath |

- **步骤**：
  1. 打开 Base（例：`#/w30hbjoc/pw4yksn9i7x1fx4`）→ Data Sources → **New Data Source** / **Add Source**。
  2. 选择 **SQL Server**（或选已有 SQL Server Connection）并填写 Host/Port/`Metabase_ODS`/schema。
  3. **Test connection** → **Add Source** → 等待同步任务完成。
- **期望**：
  - 测试连接成功。
  - **Add Source 不再出现 `Invalid request body`**（`BaseReq.type` 枚举含 `mssql`；port 以 number 提交）。
  - 可看到 schema/表列表；网格可打开至少一张表只读浏览。

### TC-DS-08 Add Source 请求体校验

- **步骤**：`POST /api/v2/meta/bases/{baseId}/sources`，`type=mssql`，`config.client=mssql`，`connection.port` 可为字符串（后端会强制转 number）。
- **期望**：创建任务成功完成；sources 列表出现对应 alias；任务日志无 AJV `Invalid request body`。
