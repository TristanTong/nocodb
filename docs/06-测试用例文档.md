## 2. 详细用例

### TC-ENV-01 Backend 健康检查

- **前置**：Backend 已启动。
- **步骤**：`GET http://localhost:6080/api/v1/health`
- **期望**：HTTP 200，body 含 `"message":"OK"`。

### TC-ENV-02 版本接口

- **步骤**：`GET /api/v1/version`
- **期望**：`currentVersion` 为 `0.301.2`（或与当前 package 一致）。

### TC-ENV-03 Frontend 可访问

- **步骤**：浏览器打开 `http://localhost:6100`
- **期望**：返回 NocoDB Frontend 页面（非长时间 503）。

### TC-AUTH-01 正确账号登录

- **前置**：Meta 中已有用户（如共用 `mlnoco`）。
- **步骤**：6100 登录页输入正确邮箱密码。
- **期望**：进入工作区/Base 列表。

### TC-AUTH-02 错误密码

- **步骤**：输入错误密码。
- **期望**：登录失败提示，不进入主界面。

### TC-DS-02 / TC-DS-03 海量数据源

- **前置**：Backend 含 FK SQL 兼容补丁；网络可达 `192.168.100.99:5432`。
- **步骤**：
  1. 打开 Base → 数据源页面（如 `#/nc/.../?page=data-source`）。
  2. 新增 PostgreSQL 连接：Host/Port/User/Password/Database=`metabase_rpt`。
  3. 测试连接并保存/同步。
- **期望**：
  - 连接成功。
  - **不再**出现含 `UNNEST` / `WITH ORDINALITY` / `syntax error at or near "."` 的失败。
  - 可看到 schema 下表列表（如 `dbo`）。

### TC-COMPAT-01 Vastbase SQL

- **步骤**：在 Vastbase 执行与 `relationListAll` 等价的 `generate_series` SQL。
- **期望**：执行成功（行数可为 0）。

### TC-COMPAT-02 标准 PG FK 映射

- **步骤**：创建临时 `parent/child` 表与 FK；执行等价 SQL。
- **期望**：返回 `cn=parent_id`，`rtn=parent`，`rcn=id`。

### TC-VB-01 列举 schema/表

- **前置**：`192.168.100.99` / `metabase_rpt` / 用户 `sa` 可达。
- **步骤**：连接后查询 `pg_tables`，统计 `dbo`、`py_etl` 等业务 schema 表数量。
- **期望**：连接成功；至少有一个业务 schema 含表。

### TC-VB-02 只读抽样业务表

- **步骤**：选取 `dbo` 下一张表执行 `SELECT * … LIMIT 5`。
- **期望**：查询成功（允许 0 行）；不修改数据。

### TC-VB-03/04/05 隔离表 CRUD

- **步骤**：在 `dbo`（或 `public`）创建 `_nc_auto_test_<ts>`，插入、查询、更新、删除后 DROP。
- **期望**：全流程成功；测试结束无残留表。

### TC-VB-06 错误密码

- **步骤**：使用错误密码连接 Vastbase。
- **期望**：连接失败（认证错误）。

### TC-VB-07 introspect + 表列表联调

- **步骤**：同一连接下先跑兼容 FK SQL，再列举表。
- **期望**：两者均无语法错误。

### TC-META-01 Meta 使用 PG

- **前置**：配置 `NC_DB` 指向 `mlnoco` 并重启 Backend。
- **步骤**：观察 `packages/nocodb/noco.db` 修改时间；调用需 Meta 的 API。
- **期望**：业务元数据来自 PG；本地 sqlite 文件无明显新写入。

### TC-PORT-01 双入口说明

- **步骤**：分别打开 6100 与 6080/dashboard。
- **期望**：均可登录（账号允许时）；日常打开验收以 6100 生产 UI 为准；版本号以 API 为准。

### TC-PERF-01 Frontend 打开 ≤3s

- **前置**：已执行 `pnpm start:frontend:build` 且 `pnpm start:frontend` 在 6100 监听；本机有 Chrome。
- **步骤**：`pnpm test:frontend-open` 或冒烟 `TC-PERF-01`（连续 3 次测量到登录表单可见）。
- **期望**：每次 `openMs ≤ 3000`；结果写入 `docs/reports/frontend-open-perf-latest.json`。
