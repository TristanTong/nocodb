| 项 | 内容 |
|----|------|
| 项目名称 | mlnocodb |
| 基线产品 | NocoDB Open Source（源码版本 **0.301.2**） |

| 适用环境 | Windows / Linux 本地开发与内网部署 |
| 关联方案 | [12-SQLServer数据源支持开发方案.md](./12-SQLServer数据源支持开发方案.md) |

## 1. 背景与目标

### 1.1 背景

业务侧需要一套可私有化部署的「电子表格式」数据库前端，对接已有 **PostgreSQL / 海量（Vastbase）/ SQL Server** 等数据源，降低非研发人员建表、查数、协作成本。本仓库在 NocoDB 上游基础上进行内网适配（端口、Meta 库、国产库兼容、SQL Server 外部源等）。

### 1.2 目标

1. 提供与 NocoDB 一致的多视图数据管理能力（网格、表单、看板、画廊、日历等）。
2. Meta 数据使用集中式 PostgreSQL（如 `mlnoco`），避免默认 SQLite 与生产环境割裂。
3. 支持连接外部业务库（含海量/Vastbase、**SQL Server**），完成数据源注册、schema 同步与网格读写。
4. 本地开发端口落在 6000 段（Backend **6080** / Frontend **6100**），避免与现网服务冲突。
5. 工程可源码构建；里程碑用仓库 tag 管理（如 `v0.1.0`～`v0.1.2`），与上游 `0.301.2` 版本号区分。

### 1.3 非目标

- 不替代上游 NocoDB 商业版全部 EE 能力（含 Custom Sync、官方 SQL Server EE add-on）。
- 不以改造海量库协议为目标；以「PG 驱动 + SQL 兼容」方式接入。
- **Meta 库不使用 SQL Server**；不做 Windows 集成认证（除非单独立项）。
- 不在本文档范围内部署完整 K8s/多活方案（见运维手册与 CentOS 部署文档）。

### 3.1 核心功能（继承 NocoDB）

| ID | 需求 | 优先级 |
|----|------|--------|
| F-01 | 用户注册/登录、角色与 Base 权限 | P0 |
| F-02 | 创建/管理 Workspace、Base、表、字段 | P0 |
| F-03 | 网格视图 CRUD、排序、筛选、分组 | P0 |
| F-04 | 表单 / 看板 / 画廊 / 日历等视图 | P1 |
| F-05 | 关联字段（Links）、Lookup、Rollup、公式等 | P1 |
| F-06 | 外部数据源连接（PG / MySQL / **SQL Server**）与 meta sync | P0 |
| F-07 | REST API / Token 访问 | P1 |
| F-08 | 附件、Webhook、基础自动化（视版本能力） | P2 |

### 3.2 本项目增量需求

| ID | 需求 | 优先级 | 状态 |
|----|------|--------|------|
| F-A1 | 本地 Backend **6080**，Frontend **6100**（生产构建；HMR 用 6110） | P0 | ✅ |
| F-A2 | Meta 库可配置为 PostgreSQL（`NC_DB`），对接现网 `mlnoco` | P0 | ✅ |
| F-A3 | 海量库（PG 兼容）作为外部数据源可添加并完成 introspect | P0 | ✅ |
| F-A4 | Windows 下 `pnpm bootstrap` / SDK 生成脚本可执行 | P1 | ✅ |
| F-A5 | 开发态 Frontend 绑定 `0.0.0.0`，支持 IPv4 访问 | P1 | ✅ |
| F-A6 | **SQL Server 外部数据源**：连接 / 同步 / 只读网格 / CRUD / 可选 DDL 与公式 | P0 | ✅（Phase 0～5） |
| F-A7 | 前端打开速度门禁（登录页 ≤3s）；剥离侧栏商业广告入口 | P1 | ✅ |
| F-A8 | CentOS/Docker 生产镜像可加载 `mssql` 驱动 | P1 | ✅ |

### 3.3 SQL Server 能力边界（F-A6 细化）

| 能力 | 要求 |
|------|------|
| 连接与同步 | SQL 账号；`searchPath` 支持非 `dbo`（如 `UFDATA`） |
| 读写 | 网格 CRUD；IDENTITY 回填；`is_data_readonly` 可禁止写 |
| DDL | 默认 `is_schema_readonly` 禁止改结构；关闭后可 API/UI 建表加列 |
| 公式 | `LEN`/`TRIM`/`IF`/`NOW` 等可用；`REGEX_*`/`ARRAY*`/`DATEADD` 等 UI 禁用 |
| 不做 | Meta=MSSQL、Custom Sync、Windows Auth、跨 schema Links 完整保证 |

## 4. 非功能需求

| ID | 类别 | 要求 |
|----|------|------|
| NF-01 | 可用性 | 前后端独立启停；`/api/v1/health` 可用；低内存可用 `start:backend:lite` |
| NF-02 | 兼容性 | Meta：PostgreSQL；外部源：标准 PG + Vastbase + **SQL Server（mssql）** |
| NF-03 | 安全 | 凭据存 `.env`（不入库）；JWT 鉴权；禁止把库密码提交 Git |
| NF-04 | 可维护 | Monorepo + pnpm；文档集中于 `/docs`；compat 脚本可重复跑 |
| NF-05 | 性能 | 单实例内网；6100 生产 UI 首屏目标 ≤3s |

## 5. 约束与假设

1. 运行时 Node.js ≥ 22；包管理仅允许 pnpm。
2. 与现网共用 Meta 库时，需注意多实例同时写 Meta 的风险。
3. 海量库报告版本类似 PostgreSQL 9.2.x 时，部分高级 SQL（如 `UNNEST … WITH ORDINALITY`）不可用，需走兼容 SQL。
4. 日常开发 UI 使用 **6100**；6080 `/dashboard` 为后端内置静态包，非热更新源码。
5. 上游自 `2026.06.1` 起将 SQL Server 标为 EE add-on；本仓库采用**历史 CE 客户端 + 公开 SDK**本地移植，不依赖 EE 授权。

## 6. 验收标准（摘要）

1. `pnpm bootstrap` 后可启动 Backend/Frontend（低内存可用 `pnpm start:backend:lite`）。
2. Meta 指向 PostgreSQL 后，登录可见现网 Base/用户数据（权限允许时）。
3. 可添加海量库数据源（如 `metabase_rpt`），不再因外键 introspect SQL 语法错误失败。
4. 可添加 SQL Server 源：测试连接 → 同步 → 网格读写；DDL/公式按 docs/06、docs/12 验收脚本通过。
5. 文档齐全且与实际端口、配置、发版 tag 一致。
