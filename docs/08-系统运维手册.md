## 0. 环境拓扑（测试 / 生产）

| 角色 | 主机 | 说明 |
|------|------|------|
| **测试环境** | `192.168.100.89` | 应用 + 本机 Meta PG；可做外网映射试验 |
| **正式生产** | `192.168.100.93` | 应用（与 Dify 等共机）；Meta 在独立库机 |
| 生产 Meta PG | `192.168.100.97:5432` / `mlnoco` | 仅生产 API 使用 |
| 测试 Meta PG | `192.168.100.89:5432` / `mlnoco` | 同机 Docker `postgres` |
| 外网映射（测试） | `http://oa.medlinket.com:19999` → `192.168.100.89:80` | 高端口，部分运营商/公司网可能拦截 |

部署目录（两环境相同约定）：`/opt/mlnocodb/`（`docker-compose.yml`、`nginx.conf`、`data/`、UI 静态目录）。

访问入口：

| 环境 | 推荐入口 | API 直连 |
|------|----------|----------|
| 测试 100.89 | `http://192.168.100.89/`（nginx:80） | `:6080` |
| 生产 100.93 | `http://192.168.100.93/`（nginx:80） | `:6080` |

容器角色（两环境）：`mlnocodb-nginx` + `mlnocodb-api` + `mlnocodb-ui`。

### 0.1 测试 vs 生产：部署与功能差异（2026-09-03 探查）

| 项 | 测试 `192.168.100.89` | 生产 `192.168.100.93` |
|----|----------------------|------------------------|
| 发布标签 / 镜像 | 库内有 `mlnocodb:0.1.3`；**运行中 API 钉死在旧层** `d2e3d15a6a68`（compose 写死 image digest） | **`mlnocodb:0.1.1`**（`4bc6c811d608`） |
| 上报版本 `/api/v1/version` | `currentVersion` **0.301.3** | **0.301.2** |
| Meta `NC_DB` | 本机 `192.168.100.89:5432` / `mlnoco` | **`192.168.100.97:5432`** / `mlnoco` |
| `NC_PUBLIC_URL` | `http://oa.medlinket.com:19999` | `http://192.168.100.93` |
| UI `NUXT_PUBLIC_NC_BACKEND_URL` | 公网域名；nginx **`sub_filter` → `window.location.origin`**（外网同源） | 写死 `http://192.168.100.93`（无 sub_filter） |
| nginx 反代 | `/api/` `/jobs/` `/download/` `/dl/` `/dltemp/` `/socket.io/`；`Host $http_host` | 同上路径齐全；`Host $host`（无端口透传 / 无同源替换） |
| 容器内 `mssql` npm 包 | **有**（`require('mssql')` OK） | **无**（`mssql_pkg_missing`） |
| `main.js` 内 `MssqlClient` / `mssql` 分支 | **当前运行包无**（build 目录有含 MSSQL 的新包 `5599316` 字节，未挂进运行容器） | **无** |
| SQL Server 数据源 | 驱动包在；完整 MSSQL 业务分支需用含 `MssqlClient` 的 `main.js` 重建/热更后再验 | **不可用**（缺驱动 + 旧 bundle） |
| 行拖动顺序 `nc_order` | Meta 已修：**全部 `Order`**（206） | Meta 仍混杂：`Order` 76 / `Decimal` 168 / `Number` 1 → 多数表**无拖动手柄** |
| Meta 规模（约） | 表约 308；Base 约 28 | Base 约 28（与测试同量级，库在 97） |
| 同机其它服务 | 主要为 mlnocodb + 本机 PG | **共驻 Dify** 等（443/8080 等，勿与 mlnocodb:80 混淆） |
| UI 静态目录 | `/opt/mlnocodb/ui-output` | `/opt/mlnocodb/ui` |

**结论（运维视角）**

1. 生产仍停在 **v0.1.1 / 0.301.2**，测试名义 **v0.1.3 / 0.301.3**，但测试运行层尚未稳定切到含完整 MSSQL 的 `main.js`。
2. 生产缺 **`mssql` 包**，外接 SQL Server 会失败；升到测试同款镜像前不要在生产开 MSSQL 源。
3. 测试已做外网同源与 `nc_order` 修复；生产未做对应 Meta 修复与公网同源策略。
4. 向生产升级时建议清单：构建 `mlnocodb:0.1.3`（`Dockerfile.centos` + 当前 `docker/main.js` + `npm install mssql`）→ 更新 compose 镜像标签（勿钉死旧 digest）→ 对齐 nginx（jobs/dl + 按需 sub_filter）→ 修复 97 库 `nc_order` Decimal→Order → 健康检查与 MSSQL 冒烟。

## 1. 运行时依赖

| 依赖 | 要求 |
|------|------|
| Node.js | ≥ 22 |
| pnpm | 9.x（推荐与锁文件一致） |
| 网络 | 可达 Meta PG；按需可达业务库（含 SQL Server） |
| Meta DB | PostgreSQL（推荐）；或 SQLite（仅试用）。**Meta 不用 SQL Server** |
| OS | Windows Server / Linux |
| 可选驱动 | 外部 SQL Server 源需运行时 `mssql`（`tedious`）包 |

可选：Docker。CentOS 镜像见 `packages/nocodb/Dockerfile.centos`（`FROM nocodb/nocodb:0.301.2` + 覆盖 `main.js` + **`npm install mssql`**）。

## 2. 安装与初始化

```bash
git clone <repo> mlnocodb
cd mlnocodb
pnpm bootstrap
```

Windows 注意：需能完成 `nocodb-sdk` 构建（`generate:sdk` 已修）。

## 3. 配置

### 3.1 Backend 环境变量

创建 `packages/nocodb/.env`（勿提交 Git）：

```env
NC_DB=pg://192.168.100.89:5432?u=postgres&p=Pass%40w0rd&d=mlnoco
NC_DISABLE_TELE=true
NODE_ENV=development
```

| 变量 | 说明 |
|------|------|
| `NC_DB` | Meta 库；密码特殊字符 URL 编码 |
| `NC_AUTH_JWT_SECRET` | JWT 密钥；多实例应一致 |
| `NC_PUBLIC_URL` | 对外访问根 URL（按需） |
| `PORT` | 覆盖默认 6080 |

| 环境 | Meta 示例 |
|------|-----------|
| 本地开发（连测试库） | `192.168.100.89:5432` / `mlnoco` |
| **测试环境 100.89** | 同机 `192.168.100.89:5432` / `mlnoco` |
| **正式生产 100.93** | Meta 在 **`192.168.100.97:5432`** / `mlnoco`（应用在 93） |

### 3.2 Frontend

默认连接 `http://localhost:6080`。跨机访问时设置：

```bash
set NUXT_PUBLIC_NC_BACKEND_URL=http://<backend-host>:6080
pnpm start:frontend:build
pnpm start:frontend
```

## 4. 启停

### 4.1 推荐模式（6100 生产构建，首屏 ≤3s）

```bash
pnpm start:frontend:build   # 首次或前端代码变更后

# 终端 1 — 低内存开发机推荐 lite
pnpm start:backend:lite
# 或完整：pnpm start:backend

# 终端 2
pnpm start:frontend
```

| 服务 | URL |
|------|------|
| API | http://localhost:6080 |
| 健康 | http://localhost:6080/api/v1/health |
| UI（快） | http://localhost:6100 |
| UI HMR | http://localhost:6110（`pnpm start:frontend:dev`） |
| 内置 UI | http://localhost:6080/dashboard |

> `pnpm start:frontend` 托管**生产构建**。改 `nc-gui` 请用 `start:frontend:dev`（6110），改完后再 build 刷新 6100。

### 4.2 停止

结束对应终端进程，或结束占用 6080/6100/6110 的 Node 进程。

### 4.3 生产简述

- 构建前端静态资源并发布到 `nc-lib-gui`，或独立托管 Frontend。
- Backend `start:prod` / Docker 镜像（见 `Dockerfile.centos`、`docker-compose/`）。
- 前置 Nginx/Traefik 做 HTTPS 与反向代理。
- 本地验收：`pnpm test:frontend-open`（打开登录页 ≤3000ms）。
- **CentOS 7.6 内网快速部署**：见 [11-CentOS7快速部署.md](./11-CentOS7快速部署.md)。

## 5. 备份与恢复

### 5.1 Meta（PostgreSQL）

```bash
pg_dump -h <meta-host> -U postgres -d mlnoco -F c -f mlnoco_$(date +%Y%m%d).dump
pg_restore -h ... -U postgres -d mlnoco --clean mlnoco_YYYYMMDD.dump
```

### 5.2 业务库

按各业务库规范备份（含 SQL Server）；NocoDB 不替代业务库备份。

### 5.3 附件

若使用本地存储目录，需一并备份 Tool Dir / 上传目录（`NC_TOOL_DIR` 等）。

## 8. 外部 SQL Server（运维要点）

| 项 | 说明 |
|----|------|
| 默认端口 | `1433/tcp`；命名实例或自定义端口以业务为准（测试库曾用 `5678`） |
| 防火墙 | 应用主机 → SQL Server 主机端口放行；勿对公网裸开 `sa` |
| TLS / Encrypt | 内网常关 `encrypt` 或开 `trustServerCertificate`；生产按证书策略 |
| 认证 | 仅 SQL 登录；Windows Auth 未做 |
| Schema | 业务表常在非 `dbo` schema；同步前确认 `searchPath` |
| Docker | 构建后容器内应能 `require('mssql')`；否则 Add Source / CRUD 失败 |
| 验收脚本 | `pnpm test:mssql-wiring`；真库时设 `NC_MSSQL_*` + `test:mssql-phase2`～`phase4` |
| 结构变更 | 默认 schema 只读；开放 DDL 前评估对业务库影响 |

## 9. 常见故障

| 现象 | 排查 |
|------|------|
| 6100 连接失败、6080 正常 | Frontend 进程；`host: 0.0.0.0`；防火墙 |
| 启动后仍用 SQLite | `.env` 是否在 `packages/nocodb` 且含 `NC_DB` |
| 登录用户与预期不符 | 是否连错 Meta；JWT Secret 是否变化 |
| Backend OOM / rspack 失败 | 改用 `pnpm start:backend:lite`；加大 `NODE_OPTIONS` |
| 添加海量源 SQL 语法错 | 确认 PgClient 兼容补丁并重启 |
| 添加 SQL Server / `Cannot find module 'mssql'` | 依赖安装；Docker 含 mssql 并重建 |
| SQL Server 同步 0 表 | `searchPath` 是否为真实业务 schema |
| 建表 `Incorrect syntax near ','` | 确认已部署 nvarchar 长度/scale 修复 |
| DDL 403 schema read-only | 关闭源的「禁止改结构」 |
| Git push 失败 | SSH key / Token；443 网络 |
| 6080 与 6100 UI 不一致 | 预期；开发用 6100 |
| 外网域名能打开但不能登录 / Network Error | UI 是否写死内网 IP；经 nginx 应用同源（`window.location.origin`） |
| `oa…:19999` 部分网络打不开 | 高端口拦截 / NAT 回流；优先改 80/443 反代 |
| 表格无行拖动手柄 | `nc_order` 的 `uidt` 须为 `Order`（非 Decimal）；视图勿开排序 |
| SQL Server「Database is not supported is not implemented」 | 运行中 `main.js` 缺 `mssql` 分支；重建并部署含 MSSQL 的 bundle + `mssql` 包 |

## 10. 发布与回滚

1. 合并变更到发布分支。
2. 需要时打 tag（例：`v0.1.2`）并 push；**非每次功能合并都必须打 tag**。
3. 目标环境更新代码 → 构建/安装依赖 → 重启；Docker 需重建含 `mssql` 的镜像。
4. 回滚：切换至上一 tag/commit，重启；Meta 若已跑迁移需按策略回滚（慎用）。

```bash
git push -u origin HEAD
# 仅在明确要求时：
# git tag v0.1.x && git push origin v0.1.x
```

已发布里程碑：`v0.1.0`、`v0.1.1`、`v0.1.2`（SQL Server MVP）、`v0.1.3`（DDL/公式/文档/Docker mssql）、`v0.1.4`/`v0.1.5`（mlhr）、`v0.1.6`（MSSQL 稳定：meta-diff/count、无主键自然键、EREQUEST）。

## 11. 安全运维

1. `.env`、数据源密码不进仓库。
2. 限制 Meta / 业务库安全组仅应用主机可达。
3. 定期轮换 DB 密码与 JWT Secret（轮换 JWT 会使现有 Token 失效）。
4. 共用现网 Meta 的开发实例：避免破坏性迁移与自动化写业务表。
