# 系统运维手册

| 项 | 内容 |
|----|------|
| 项目 | mlnocodb |
| 文档版本 | v0.1.0 |
| 源码版本 | 0.301.2 |

## 1. 运行时依赖

| 依赖 | 要求 |
|------|------|
| Node.js | ≥ 22 |
| pnpm | 9.x（推荐与锁文件一致） |
| 网络 | 可达 Meta PG；按需可达业务库 |
| Meta DB | PostgreSQL（推荐）；或 SQLite（仅试用） |
| OS | Windows Server / Linux |

可选：Docker（用于测试依赖或生产镜像）。

## 2. 安装与初始化

```bash
git clone <repo> mlnocodb
cd mlnocodb
pnpm bootstrap
```

Windows 注意：需能完成 `nocodb-sdk` 构建（已修复 `generate:sdk` 脚本）。

## 3. 配置

### 3.1 Backend 环境变量

创建 `packages/nocodb/.env`（勿提交 Git）：

```env
NC_DB=pg://192.168.100.89:5432?u=postgres&p=Pass%40w0rd&d=mlnoco
NC_DISABLE_TELE=true
NODE_ENV=development
```

| 变量 | 说明 |
|------|------|
| `NC_DB` | Meta 库；密码特殊字符 URL 编码 |
| `NC_AUTH_JWT_SECRET` | JWT 密钥；多实例应一致 |
| `NC_PUBLIC_URL` | 对外访问根 URL（按需） |
| `PORT` | 覆盖默认 6080 |

### 3.2 Frontend

默认连接 `http://localhost:6080`。跨机访问时设置：

```bash
# 示例（生产 UI 需先 build）
set NUXT_PUBLIC_NC_BACKEND_URL=http://<backend-host>:6080
pnpm start:frontend:build
pnpm start:frontend
```

## 4. 启停

### 4.1 推荐模式（6100 生产构建，首屏 ≤3s）

```bash
# 首次或前端代码变更后
pnpm start:frontend:build

# 终端 1
pnpm start:backend

# 终端 2 — 提供 http://localhost:6100/
pnpm start:frontend
```

| 服务 | URL |
|------|------|
| API | http://localhost:6080 |
| 健康 | http://localhost:6080/api/v1/health |
| UI（快） | http://localhost:6100 |
| UI HMR | http://localhost:6110（`pnpm start:frontend:dev`） |
| 内置 UI | http://localhost:6080/dashboard |

> 说明：`pnpm start:frontend` 已改为托管 **生产构建**（非 Vite 热更新）。改 `nc-gui` 源码请用 `pnpm start:frontend:dev`（6110），改完后再 `start:frontend:build` 刷新 6100。

### 4.2 停止

结束对应终端进程，或结束占用 6080/6100/6110 的 Node 进程。

### 4.3 生产简述

- 构建前端静态资源并发布到 `nc-lib-gui`，或独立托管 Frontend。
- Backend `start:prod` / Docker 镜像（见上游与 `docker-compose/`）。
- 前置 Nginx/Traefik 做 HTTPS 与反向代理。
- 本地验收：`pnpm test:frontend-open`（打开登录页 ≤3000ms）。
- **CentOS 7.6 内网快速部署**：见 [11-CentOS7快速部署.md](./11-CentOS7快速部署.md)（推荐 Docker 自建镜像，勿在宿主机直接装 Node 22）。
## 5. 备份与恢复

### 5.1 Meta（PostgreSQL）

```bash
pg_dump -h 192.168.100.89 -U postgres -d mlnoco -F c -f mlnoco_$(date +%Y%m%d).dump
# 恢复
pg_restore -h ... -U postgres -d mlnoco --clean mlnoco_YYYYMMDD.dump
```

### 5.2 业务库

按各业务库规范备份；NocoDB 不替代业务库备份。

### 5.3 附件

若使用本地存储目录，需一并备份 Tool Dir / 上传目录（由 `NC_TOOL_DIR` 等决定）。

## 6. 监控与巡检

| 项 | 方法 |
|----|------|
| 存活 | 定时请求 `/api/v1/health` |
| 版本 | `/api/v1/version` |
| 进程 | Node 端口 6080/6100 监听 |
| Meta | `pg_stat_activity`、连接数 |
| 磁盘 | 日志与附件目录 |

## 7. 日志

- 开发态：Backend 终端 Nest/ rspack 输出。
- 建议生产：进程管理器（pm2/systemd）重定向日志并切割。

## 8. 常见故障

| 现象 | 排查 |
|------|------|
| 6100 连接失败、6080 正常 | 确认 Frontend 进程；`host: 0.0.0.0`；防火墙 |
| 启动后仍用 SQLite | 检查 `.env` 是否在 `packages/nocodb` 且含 `NC_DB` |
| 登录用户与预期不符 | 是否连错 Meta；JWT Secret 是否变化导致会话失效 |
| 添加海量源 SQL 语法错 | 确认已部署 PgClient 兼容补丁并重启 Backend |
| Git push 失败 | SSH key / Token；443 网络 |
| 6080 与 6100 UI 不一致 | 预期现象；开发用 6100 |

## 9. 发布与回滚

1. 合并变更到发布分支。
2. 打 tag（例：`v0.1.0`）并 push。
3. 目标环境更新代码 → `pnpm bootstrap`（或安装依赖）→ 重启服务。
4. 回滚：切换至上一 tag/commit，重启；Meta 若已跑迁移需按迁移策略回滚（慎用）。

```bash
git push -u origin HEAD
git push origin v0.1.0
```

## 10. 安全运维

1. `.env`、数据源密码不进仓库。
2. 限制 Meta / 业务库安全组仅应用主机可达。
3. 定期轮换 DB 密码与 JWT Secret（轮换 JWT 会使现有 Token 失效）。
4. 共用现网 Meta 的开发实例：避免跑破坏性迁移与自动化写库。
