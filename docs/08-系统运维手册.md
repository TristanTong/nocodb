# 系统运维手册

| 项 | 内容 |
|----|------|
| 项目 | mlnocodb |
| 文档版本 | **v0.1.3** |
| 源码版本 | 0.301.2 |

## 1. 运行时依赖

| 依赖 | 要求 |
|------|------|
| Node.js | ≥ 22 |
| pnpm | 9.x（推荐与锁文件一致） |
| 网络 | 可达 Meta PG；按需可达业务库（含 SQL Server） |
| Meta DB | PostgreSQL（推荐）；或 SQLite（仅试用）。**Meta 不用 SQL Server** |
| OS | Windows Server / Linux |
| 可选驱动 | 外部 SQL Server 源需运行时 `mssql`（`tedious`）包 |

可选：Docker。CentOS 镜像见 `packages/nocodb/Dockerfile.centos`（`FROM nocodb/nocodb:0.301.2` + 覆盖 `main.js` + **`npm install mssql`**）。

## 2. 安装与初始化

```bash
git clone <repo> mlnocodb
cd mlnocodb
pnpm bootstrap
```

Windows 注意：需能完成 `nocodb-sdk` 构建（`generate:sdk` 已修）。

## 3. 配置

### 3.1 Backend 环境变量

创建 `packages/nocodb/.env`（勿提交 Git）：

```env
NC_DB=pg://192.168.100.89:5432?u=postgres&p=Pass%40w0rd&d=mlnoco
NC_DISABLE_TELE=true
NODE_ENV=development
```

| 变量 | 说明 |
|------|------|
| `NC_DB` | Meta 库；密码特殊字符 URL 编码 |
| `NC_AUTH_JWT_SECRET` | JWT 密钥；多实例应一致 |
| `NC_PUBLIC_URL` | 对外访问根 URL（按需） |
| `PORT` | 覆盖默认 6080 |

| 环境 | Meta 示例 |
|------|-----------|
| 本地开发 | `192.168.100.89` / `mlnoco` |
| 生产示例 | `192.168.100.93` / `mlnoco`（以实际为准） |

### 3.2 Frontend

默认连接 `http://localhost:6080`。跨机访问时设置：

```bash
set NUXT_PUBLIC_NC_BACKEND_URL=http://<backend-host>:6080
pnpm start:frontend:build
pnpm start:frontend
```

## 4. 启停

### 4.1 推荐模式（6100 生产构建，首屏 ≤3s）

```bash
pnpm start:frontend:build   # 首次或前端代码变更后

# 终端 1 — 低内存开发机推荐 lite
pnpm start:backend:lite
# 或完整：pnpm start:backend

# 终端 2
pnpm start:frontend
```

| 服务 | URL |
|------|------|
| API | http://localhost:6080 |
| 健康 | http://localhost:6080/api/v1/health |
| UI（快） | http://localhost:6100 |
| UI HMR | http://localhost:6110（`pnpm start:frontend:dev`） |
| 内置 UI | http://localhost:6080/dashboard |

> `pnpm start:frontend` 托管**生产构建**。改 `nc-gui` 请用 `start:frontend:dev`（6110），改完后再 build 刷新 6100。

### 4.2 停止

结束对应终端进程，或结束占用 6080/6100/6110 的 Node 进程。

### 4.3 生产简述

- 构建前端静态资源并发布到 `nc-lib-gui`，或独立托管 Frontend。
- Backend `start:prod` / Docker 镜像（见 `Dockerfile.centos`、`docker-compose/`）。
- 前置 Nginx/Traefik 做 HTTPS 与反向代理。
- 本地验收：`pnpm test:frontend-open`（打开登录页 ≤3000ms）。
- **CentOS 7.6 内网快速部署**：见 [11-CentOS7快速部署.md](./11-CentOS7快速部署.md)。

## 5. 备份与恢复

### 5.1 Meta（PostgreSQL）

```bash
pg_dump -h <meta-host> -U postgres -d mlnoco -F c -f mlnoco_$(date +%Y%m%d).dump
pg_restore -h ... -U postgres -d mlnoco --clean mlnoco_YYYYMMDD.dump
```

### 5.2 业务库

按各业务库规范备份（含 SQL Server）；NocoDB 不替代业务库备份。

### 5.3 附件

若使用本地存储目录，需一并备份 Tool Dir / 上传目录（`NC_TOOL_DIR` 等）。

## 8. 外部 SQL Server（运维要点）

| 项 | 说明 |
|----|------|
| 默认端口 | `1433/tcp`；命名实例或自定义端口以业务为准（测试库曾用 `5678`） |
| 防火墙 | 应用主机 → SQL Server 主机端口放行；勿对公网裸开 `sa` |
| TLS / Encrypt | 内网常关 `encrypt` 或开 `trustServerCertificate`；生产按证书策略 |
| 认证 | 仅 SQL 登录；Windows Auth 未做 |
| Schema | 业务表常在非 `dbo` schema；同步前确认 `searchPath` |
| Docker | 构建后容器内应能 `require('mssql')`；否则 Add Source / CRUD 失败 |
| 验收脚本 | `pnpm test:mssql-wiring`；真库时设 `NC_MSSQL_*` + `test:mssql-phase2`～`phase4` |
| 结构变更 | 默认 schema 只读；开放 DDL 前评估对业务库影响 |

## 9. 常见故障

| 现象 | 排查 |
|------|------|
| 6100 连接失败、6080 正常 | Frontend 进程；`host: 0.0.0.0`；防火墙 |
| 启动后仍用 SQLite | `.env` 是否在 `packages/nocodb` 且含 `NC_DB` |
| 登录用户与预期不符 | 是否连错 Meta；JWT Secret 是否变化 |
| Backend OOM / rspack 失败 | 改用 `pnpm start:backend:lite`；加大 `NODE_OPTIONS` |
| 添加海量源 SQL 语法错 | 确认 PgClient 兼容补丁并重启 |
| 添加 SQL Server / `Cannot find module 'mssql'` | 依赖安装；Docker 含 mssql 并重建 |
| SQL Server 同步 0 表 | `searchPath` 是否为真实业务 schema |
| 建表 `Incorrect syntax near ','` | 确认已部署 nvarchar 长度/scale 修复 |
| DDL 403 schema read-only | 关闭源的「禁止改结构」 |
| Git push 失败 | SSH key / Token；443 网络 |
| 6080 与 6100 UI 不一致 | 预期；开发用 6100 |

## 10. 发布与回滚

1. 合并变更到发布分支。
2. 需要时打 tag（例：`v0.1.2`）并 push；**非每次功能合并都必须打 tag**。
3. 目标环境更新代码 → 构建/安装依赖 → 重启；Docker 需重建含 `mssql` 的镜像。
4. 回滚：切换至上一 tag/commit，重启；Meta 若已跑迁移需按策略回滚（慎用）。

```bash
git push -u origin HEAD
# 仅在明确要求时：
# git tag v0.1.x && git push origin v0.1.x
```

已发布里程碑：`v0.1.0`、`v0.1.1`、`v0.1.2`（SQL Server MVP）。Phase 3～5 以提交合入，未强制升版本。

## 11. 安全运维

1. `.env`、数据源密码不进仓库。
2. 限制 Meta / 业务库安全组仅应用主机可达。
3. 定期轮换 DB 密码与 JWT Secret（轮换 JWT 会使现有 Token 失效）。
4. 共用现网 Meta 的开发实例：避免破坏性迁移与自动化写业务表。
